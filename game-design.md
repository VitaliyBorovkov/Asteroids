# Asteroid → Black Hole (рабочее название: steroid.io)

## Концепт
Unity-прототип. Игрок управляет астероидом в космосе. Цель — вырастить его из маленького камня в чёрную дыру, поглощающую всё на пути, через столкновения с другими астероидами.

## Формат и скоуп
- 2.5D: 3D-модели, движение ограничено 2D-плоскостью
- Платформа: PC/Steam
- Стадия: быстрый прототип механики (без монетизации, без лидерборд и т.п.)
- Реализация: Claude Code — этот документ является implementation-ready брифом, чтобы минимизировать токены на дизайн-ресёрч там.

## Архитектура (решено)
- **DI: VContainer** (автор hadashiA), не Zenject/Extenject. Extenject не обновлялся с пререлиза 9.3.1 (июль 2022), фактически заморожен. VContainer — активно поддерживаемый, 5-10x быстрее на resolve, использует его даже официальный Netcode-тьюториал Unity. Концепции те же: `LifetimeScope` (аналог SceneContext), `builder.Register<T>(Lifetime.Singleton)` (аналог `Container.Bind<T>().AsSingle()`), `[Inject]`-поля без изменений. Пакет: OpenUPM `jp.hadashikick.vcontainer`, либо git URL с GitHub hadashiA/VContainer — точный путь проверить в README репозитория на момент установки.
- **Реактивность: R3** (Cysharp), не UniRx. Автор UniRx (neuecc) сам рекомендует переходить на R3 — UniRx официально legacy/архивирован. R3 того же автора экосистемы, что и UniTask — лучше производительность, actively maintained. Нужны два пакета: core R3 + R3.Unity. Все изменяемые статы — `ReactiveProperty<T>` (пыль/валюта, масса/текущая стадия, статы веток), UI/VFX подписываются на поток без поллинга в Update.
- **Async: UniTask** (Cysharp) — таймеры и последовательности событий (например, тайминг "метеоритного дождя"), вместо корутин. Нативно интегрируется с VContainer.
- **Addressables — осознанно НЕ подключаем.** Прямые ссылки на префабы (через LifetimeScope/сериализованные поля) или `Resources`. Пересмотреть только если появится реальная задача динамической/потоковой загрузки контента.

### Минимальный набор зарегистрированных сервисов (RootLifetimeScope)
- `UpgradeManager` — валюта (пыль), применение эффектов узлов дерева, экспонирует стат-бонусы как `ReactiveProperty<float>`/`int`.
- `GrowthController` — текущая масса и стадия (`ReactiveProperty<int> CurrentStage`), переход между стадиями только по покупке апгрейда роста.
- `TalentTree` — граф узлов, состояние "открыт/не открыт", проверка зависимостей.
- `EventSystem` — реестр ивентов (unlock + параметры), на старте только "метеоритный дождь".

## Тесты
Unity Test Framework (`com.unity.test-framework`), только Edit Mode, только чистая логика без MonoBehaviour:
- `CollisionSizeResolver.GetHitsToBreak` / `IsBreakable`
- Переходы между стадиями роста по порогам
- Расчёт стоимости/применения апгрейдов в `UpgradeManager`

MonoBehaviour-поведение (столкновения, спавнер, UI, ощущение геймплея) не тестируется автоматически на этом этапе — проверяется руками во время итерации прототипа.

## Управление и камера
- Point-and-click: клик по точке на экране — астероид игрока перемещается туда.
- Камера отъезжает/масштабируется по мере роста игрока (не фиксированный FOV).

## Core loop: столкновения
- Игрок врезается в астероиды. Урон однонаправленный — у игрока нет риска/контр-урона при столкновении (осознанное решение).
- **Формула количества ударов**: `hits = 1 + floor((ratio - 1) / step)`, где `ratio = массаЦели / массаИгрока`, `step` — настраиваемый параметр баланса (например, +1 удар за каждые +50% массы).
- **Нет понятия "неразбиваемый астероид".** Любая цель разбивается, разница только в количестве ударов.
- При разрушении цель оставляет космическую пыль, игрок её собирает.

## Рост массы
- Масса игрока растёт **исключительно через покупку апгрейда роста в дереве талантов за пыль** — не автоматически от факта поедания астероидов. В дереве есть уровни, по достижении которых астероид игрока увеличивается в размере (меняет стадию).
- Столкновения — источник пыли (валюты), а не прямого роста массы.

## Визуальные стадии роста
5 стадий (3 промежуточные между стартом и финалом), привязка к реальной астрономической классификации по массе:

1. **Метеороид/камень** (старт) — неправильная форма, вытянутая, кратеры.
2. **Астероид** — крупнее, неправильная форма, больше деталей поверхности.
3. **Карликовая планета** — форма становится сферической (hydrostatic equilibrium). Встроенный примитив-сфера достаточен визуально.
4. **Газовый гигант/протозвезда** — сфера светится (emission/glow), атмосфера-эффект. Привязана к порогу разблокировки гравитационного колодца (ветка планеты/чёрной дыры).
5. **Чёрная дыра** (финал) — отдельный шейдер: горизонт событий/аккреционный диск, партиклы и постпроцесс, без отдельной 3D-модели.

Все 5 стадий оставлены на старте — дёшево для прототипа (стадия 3 — примитив, стадия 4 — материал с эмиссией, стадия 5 — шейдер/партиклы, новых моделей не требуется).

## Прогрессия: дерево талантов
- Валюта: космическая пыль.
- **Одно дерево, три ветки от общего корня**, с зависимостями между узлами (не плоский список, не три изолированные колонки):
  1. **Астероид/игрок** — статы роста (скорость и т.п.), узлы роста размера (стадии 1→2→3), магнитное притяжение пыли (радиус подбора).
  2. **Планета/чёрная дыра** — апгрейды роста до стадий 4→5; включает гравитационное притяжение **объектов** (не только пыли), разблокируется при достижении стадии 4.
  3. **Внешний мир/события** — разблокировка событий и прокачка их параметров. **На старте только один ивент — "метеоритный дождь"** (частота, количество астероидов в волне, экранный индикатор-стрелка направления). Остальные события — не реализуются сейчас, только оставляем для них общую абстракцию, чтобы не переписывать систему при добавлении второго ивента.
- Узлы двух типов, разных по структуре данных:
  - **Статовые** — непрерывная прокачка числового параметра (несколько уровней, линейный рост значения).
  - **Событийные** — unlock-узел + свои отдельно прокачиваемые параметры. Нужен общий интерфейс/база `GameEvent` (имя, unlock-флаг, список параметров), чтобы "метеоритный дождь" был первой реализацией, а не единственно возможной.

## Гравитационное притяжение (эскалация по дереву)
- Ранний тир (ветка астероида): магнит для пыли — увеличивает радиус подбора, не трогает другие астероиды.
- Поздний тир (ветка планеты/чёрной дыры, от стадии 4): гравитационный колодец, притягивающий сами астероиды/объекты.

## Условие завершения
Пока только одно: становление чёрной дырой (стадия 5) = конец (победа). Что происходит после — не определено, вне скоупа текущего прототипа.
